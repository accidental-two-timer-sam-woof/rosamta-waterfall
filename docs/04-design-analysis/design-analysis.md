# 設計分析

## 1. 分析基準

需求範圍、優先序與驗收條件以 [SRS](../02-srs/srs.md) 為準。

第一版須涵蓋所有 `essential` 需求。`conditional` 與 `optional` 需求依 SRS §2.6 決定是否納入；延後的需求及原因列在 SRS 附錄 A.3。

## 2. 系統分工與設計選擇

rosamta 以同一個命令列程式提供各項子指令（IF-001）。CLI 在載入設定前處理說明請求。每個子指令的說明列出用途、參數、可能的 exit code 與至少一個範例，未初始化、沒有來源目錄或網路時也能顯示（IF-002）。

| 選項 | 影響 | 分析結論 |
| --- | --- | --- |
| 分開或共用預覽與套用的規劃流程 | 分開規劃容易讓目標路徑、drift、接管與清除的判定出現差異 | 預覽與套用共用 `Planner`。套用取得寫入鎖後重新讀取資料及規劃，整批預檢與模式檢查通過才執行。FR-PLN-006 的比較前提見 §6 |
| 邊檢查邊寫入，或先完成整批預檢 | 邊檢查邊寫入，可能改動部分輸出後才發現碰撞 | `PreflightChecker` 在寫入前檢查整批計畫。第一版一次彙整能獨立判定的預檢錯誤（USE-004）。`Executor` 只接收通過檢查的計畫，執行失敗時啟動回復（FR-PLN-007、FR-APL-002） |
| 分散或集中檔案操作 | 分散處理容易讓接管、清除與回復採用不同的連結或權限規則 | `FileSystem` 封裝平台檔案操作，`StateStore` 管理狀態檔，`RecoveryManager` 保存與還原套用前的資料（SEC-002、REL-001–004、PORT-001） |

| 責任 | 所需資料與結果 | SRS 需求 |
| --- | --- | --- |
| 設定載入與欄位解析 | `ConfigLoader` 載入內建資源與使用者設定，保留來源位置供診斷使用。manifest 有重複輸出名稱時，依 TOML 鍵的實際值辨識同名宣告並回報所有位置。Profile 條件內各項須全部符合，同一輸出的多個條件有一項成立即可啟用。`ValueResolver` 依內建預設值、使用者模組、Profile、本機設定的順序覆寫，並保留最終值的來源。同一層重複設定時回報各來源。`PreflightChecker` 在值解析後檢查型別、範圍、格式及必填條件，通過後才渲染範本。檢查失敗時，回報欄位名稱、違反的條件和值所在的檔案。缺少必填值時，指出欄位宣告所在的檔案 | FR-MOD-001–003、FR-MAN-004、FR-MAN-011、FR-MAN-029、FR-PRF-005–013、FR-PLN-008、DATA-001–004 |
| 範本與原樣複製 | 範本產生期望內容並提供可查詢的欄位引用。原樣複製保留來源位元組，欄位引用為空。每個內建模組至少有一個內建範本；內建範本須標示目標程式與設定格式版本 | FR-TPL-001–003、FR-TPL-006、FR-QRY-003、FR-QRY-004 |
| 預覽與套用 | 規劃使用有效設定、主機與路徑資訊、最終欄位值、目標現況和狀態紀錄。預覽列出計畫、差異及衝突處理方式。執行只使用預檢確認的期望內容，或指向該內容的執行期參照，並回報逐項結果、保留原因、接管備份位置及適用的回復資訊 | FR-PLN-001–010、FR-MAN-019、FR-APL-001–009、FR-DRF-003 |
| 管理與查詢 | `ManifestService` 負責納入、修改屬性與停止管理，並保留設定檔未受影響的註解及格式。`QueryService` 共用有效 manifest、Profile 判定、欄位解析及範本引用資訊。完整清單包含內建及未啟用的輸出，逐項列出屬性、當前平台路徑及啟用狀態。可依模組或欄位查詢引用它的輸出，也可查詢個別輸出的來源與引用 | FR-MAN-023–026、FR-MAN-030、FR-PRF-013、FR-QRY-001–004、FR-QRY-006 |
| 初始化 | 未指定遠端時，`InitializationService` 建立空來源目錄與空 manifest，不執行首次套用。指定遠端時，先取得暫存來源，確認正式位置可用才移入。若正式位置已被占用，回傳 `1`，保留既有檔案與本機設定，不進入套用。來源就緒後才建立或合併本機設定，保留本次未指定的值。首次套用沿用一般預檢、衝突處理、回報與 exit code。後續指令不必再指定來源位置 | FR-INI-001–002、FR-INI-004、FR-INI-006、FR-INI-008–011、IF-012、IF-013 |

停止管理先在狀態檔標記 `forget_pending`，再移除使用者宣告或記錄內建輸出已停止管理，最後移除狀態紀錄。若標記後的寫入失敗或程序中止，後續套用保留該項目及原紀錄，並提示重試停止管理。即使輸出已停用、仍啟用或宣告接管，也不對目標執行清除、接管或修改（FR-MAN-025）。

停止管理和套用使用同一寫入鎖。套用在取得鎖後依最新資料規劃。停止管理成功後，套用不會沿用先前預覽的計畫去改動該目標或恢復其紀錄（FR-MAN-025）。

納入管理時，先在來源目錄建立副本，再新增原樣複製的 manifest 宣告。預定位置被占用時，另選空位或回報失敗；兩種情況都須保留既有來源檔及宣告（FR-MAN-023）。

每次規劃使用同一份主機資訊、Profile 啟用結果與狀態紀錄。預檢完成前須備妥啟用輸出的期望內容。執行期參照須指向已確認的版本；執行計畫時不得重讀來源或重新渲染。若無法取得該版本，依執行失敗處理。重檢時將現況與規劃時的紀錄比對（FR-PLN-006–007、FR-APL-001–002）。

CLI 把計畫與執行結果寫到標準輸出，錯誤與警告寫到標準錯誤。預覽與查詢維持唯讀，預覽也不得執行設定中的外部命令。第一版不提供互動詢問。之後納入時，只有明確啟用互動且標準輸入連接終端機才詢問。所有必做功能須在 Linux、Windows、macOS 以一般使用者權限運作，並能以各平台的單一執行檔發佈。只有初始化取得遠端來源時可連線，並可使用 git（IF-007、IF-008、IF-013、FR-PLN-004–005、FR-QRY-006、USE-001、USE-002、DC-001、DC-004、PORT-001）。

## 3. 關鍵流程分析

### 3.1 判定目標、接管與清除

`Planner` 先判定啟用的輸出與目標路徑，再按同一套平台路徑規則檢查碰撞與 home 範圍。目標路徑碰撞時，回報衝突的目標路徑、各輸出名稱及各自在 manifest 的宣告位置（檔案與行號）。來源、本機設定、狀態、備份與暫存檔同樣受 home 寫入限制。目標是符號連結時，檢查連結本身。父目錄解析後若使寫入位置超出 home，須攔下操作（FR-MAN-007–010、FR-PLN-009、FR-PLN-010、DC-002、DC-003、SEC-002）。

manifest 的使用者範本與原樣複製路徑一律相對於來源目錄解析，與工作目錄無關。預覽、套用及實際讀檔的引用查詢只讀取來源目錄內的一般檔案。來源檔本身和父路徑中的連結均會被拒絕，即使所指位置仍在來源目錄內也一樣。若無法確認實際讀取位置，回報路徑錯誤並停止該計畫或查詢。只回傳原樣複製來源路徑的查詢不必開啟檔案。內建資源與本機設定由各自的載入流程處理（FR-MAN-005、FR-TPL-006、FR-PLN-003、FR-PLN-007、FR-QRY-003–004）。

預檢須找出同時被當成一般檔案與目錄的路徑。例如兩個輸出分別指向 `~/app` 和 `~/app/settings.toml`，即使都尚未建立，也無法同時套用。遇到這種衝突時，回報涉及的輸出與路徑，整批回傳 `1`，並保留所有既有輸出與狀態檔（FR-PLN-007、FR-APL-008、DC-003）。

預檢須保護來源目錄及其內容、本機設定、狀態檔，以及程式保留的鎖定、備份、暫存和回復位置。啟用輸出若與保留位置衝突，即使目標尚不存在或動作為「不變」，也須在預檢列出輸出、manifest 宣告位置及衝突路徑，整批回傳 `1`，輸出與狀態檔維持原狀。未配對到啟用輸出的舊紀錄若指向保留位置，清除只保留該項的檔案與紀錄，回報 `reserved`。只有保留項目時回傳 `1`，同批另有完成項目時回傳 `2`（FR-PLN-007、FR-APL-001、FR-APL-005、FR-APL-007–009、DATA-005）。

| 觀察結果 | 決策 | 依據 |
| --- | --- | --- |
| 狀態檔不存在 | 以空紀錄規劃，將既有目標視為未受管理，不產生舊檔清除計畫 | REL-003 |
| 狀態檔讀取失敗或損毀 | 預檢失敗，指出狀態檔路徑，保留既有輸出與狀態檔 | REL-004 |
| 一般檔案無紀錄，且內容已符合期望 | 直接記為受管理，不重寫內容或建立備份。之後停用或移除仍依清除規則處理 | FR-MAN-021、FR-DRF-012 |
| 一般檔案無紀錄，且內容與期望不同 | 有接管授權時先備份，再寫入並回報備份位置。未獲授權時保留原檔、回報原因，其餘項目照常套用 | FR-MAN-018–022 |
| 目標本身是符號連結 | 視為未受管理。獲授權接管時先備份連結，再以一般檔案取代連結；未獲授權時保留連結。兩種情況皆不得寫入或刪除連結所指的檔案 | SEC-002、DC-003 |
| 未受管理的目標是目錄、FIFO、裝置檔或通訊端，且未獲授權接管 | 只檢查類型，不開檔讀取。保留原項目並回報原因，其餘項目照常套用 | FR-MAN-020、FR-APL-005–008 |
| 來源或必須操作的目標類型不受支援 | 在讀取內容前核對實際類型。來源檔須是一般檔案，來源檔及父路徑不得為連結。啟用輸出的目標若被非目錄項目阻擋，且本批不會先移除該阻擋，計畫檢查回報 `preflight.unsupported-type`。無法安全讀取、備份或操作時回傳 `1`，輸出與狀態檔維持原狀 | FR-PLN-007、FR-APL-008、DC-003 |
| 原受管理輸出已移除、停用或改路徑 | 只有未由啟用輸出接續管理的舊位置才規劃清除。若無其他保留條件，確認舊目標不存在時只移除紀錄，項目為完成。確認缺檔包含目標或其父目錄不存在，以及走訪遇到非目錄、非連結的上層項目（`Missing { blocker }`）。父路徑有連結、位置無法確認、舊目標是非一般檔案、位於保留位置或停止管理未完成時，保留檔案與紀錄並回報原因。其餘情形依舊檔有無外部修改及明確刪除授權處理 | FR-DRF-012–016、FR-MAN-025、SEC-002 |

套用與清除都須核對舊紀錄、本次目標及父路徑，確認仍是原本受管理的位置。若父目錄在兩次套用間遭替換，即使新的位置仍在 home 內且檔案內容相同，也不能只憑內容比對沿用舊紀錄。無法確認位置時，清除須保留檔案與紀錄並回報原因。仍啟用的輸出則按未受管理的既有檔案處理。內容與期望不同時，有接管授權才可先備份後替換，否則保留檔案。觀測時若發生實際 I/O 讀取錯誤，規劃回報 `plan.inspect-failed`、路徑與作業系統錯誤，回傳 `1`，整批不寫入輸出或狀態檔（FR-MAN-019–021、FR-DRF-012–013、FR-DRF-016、DATA-006）。

新輸出沿用已受管理的位置時，按位置鍵配對舊紀錄，依現行輸出規則規劃，不另產生舊檔清除項目。內容與適用權限均不變時，只更新紀錄名稱。若項目因 drift 等原因保留，沿用原名稱與紀錄，待之後可完成套用或執行停止管理。

舊檔不存在、只剩紀錄時，新輸出可沿用該路徑。建立新檔時須確認位置仍空，提交前重檢與完成確認時都須核對目標仍是本批建立的檔案。成功後以新紀錄取代舊紀錄。若位置已被外部程式占用，或新檔遭替換，保留外部檔案並依執行失敗處理。若完成確認才發現不符，依回復規則處理本批提交的新狀態（FR-DRF-015、FR-APL-001–002）。

### 3.2 Drift 與狀態紀錄

狀態檔與本機設定放在來源目錄外。狀態檔記錄輸出名稱、目標路徑及兩份比較基準：實際基準用來偵測目標後續的外部修改，期望基準用來判斷來源產生的內容是否改變。基準只存比較資訊，不含輸出原文；回復快照另存。接受 drift 只更新狀態檔，不改動目標或來源（FR-DRF-001–008、DATA-005、DATA-006、SEC-001、B-17）。

假設目標原為 `A`，遭外部修改為 `B`，期望仍為 `A`。接受後實際基準為 `B`，期望基準為 `A`。原樣重跑時維持 `B`。若目標再次被改動，重新判定 drift。若改動後的內容已符合本次期望，依 FR-DRF-002 更新紀錄，再依平台與權限宣告判斷是否仍須處理屬性。若只有來源變更，且新期望恰好等於 `B`，只更新期望基準，保留目標內容與實際基準。

第一版納入 FR-DRF-008。若只有來源變更，使期望內容改為 `D`，將 `B` → `D` 列為一般更新，並滿足 FR-MOD-002 的共用欄位更新要求。

預設模式略過 drift 衝突，保留該目標及原紀錄，其他項目照常套用。使用者可指定覆寫或接受單一目標，也可將同一處理方式套用於本次所有 drift 衝突。嚴格模式只要有 drift 衝突，即使同時指定接受或覆寫，也須停止整批，不寫入任何輸出或狀態檔。回報每個衝突的輸出名稱與目標路徑，回傳 `1`。嚴格模式沒有 drift 衝突時，未接管項目依一般規則保留。全數完成或計畫為空回傳 `0`，完成與保留並存回傳 `2`，只有保留回傳 `1`（FR-DRF-003–009、FR-APL-006–009、B-3–B-5）。

### 3.3 寫入、儲存與回復

只有本批要改動目標或提交狀態時，`RecoveryManager` 才建立回復資源。先保存原狀態檔，再依各項操作保存回復所需的內容、權限與存在狀態。接管備份須在改動目標前完成，供使用者取回原檔。寫入時先備妥完整檔案再原子替換。未宣告權限時保留既有權限，單純的權限差異不列為 drift。

所有目標操作成功且通過重檢後，才由 `StateStore.commit` 提交有變更的狀態。完成確認會再核對目標與狀態檔版本，即使本批無須提交。批次完成前發生執行錯誤時，回復本批改動及原狀態，並回報原錯誤。若有項目無法安全回復，列出路徑與原因（FR-APL-001–005、FR-MAN-016、FR-MAN-019、REL-001–002）。

若本批先前接管了符號連結，回復須能還原連結本身，並保護它所指的檔案。程序在寫入時遭強制終止，單一輸出或狀態檔須維持完整的舊版或新版（REL-001、REL-002）。分別估算期望內容、單次替換的暫存檔、累積的回復快照與接管備份所需的空間，並評估磁碟空間不足時哪些操作可能失敗。

含輸出原文的暫存檔、快照與接管備份，從建立起依各平台的檔案與目錄權限規則限制存取。接管備份依保留規則保存，Linux 與 macOS 的備份保留原檔權限（SEC-003）。批次完成或回復結束後清理用不到的暫存檔與快照。批次完成後若清理失敗，只回報警告，已提交的結果仍有效。程序中止或回復失敗後留下的副本仍適用原有存取限制。套用和接受 drift 時，狀態檔都不得存入輸出原文（SEC-001）。

擷取回復快照、製作接管備份、寫入與刪除時，須確認實際操作的目標及父路徑仍符合預檢記錄的位置及存在狀態，且位於 home 內。若檔案已存在，也須確認實際操作的檔案類型及身分符合預檢所見。擷取快照或備份時，先確認實際開啟的檔案，再讀取內容。目標是符號連結時只保存連結本身。須以實際擷取的快照與接管備份核對規劃時的版本，包含內容及適用權限。清除或覆寫前也須核對實際目標仍符合該版本。即使檔案身分未變，只要擷取或操作前發現版本不同，原計畫即失效。若觀測失效或無法確認操作安全，停止該操作與後續套用，並回復本批已變更的項目（DC-002、DC-003、SEC-002、FR-APL-002–004、FR-MAN-019、FR-DRF-013）。

建立或更新時，須從本批實際寫入的檔案取得身分，並保留內容與適用屬性的比較資料。提交前重檢與完成確認都須核對所有預定回報完成的項目及其父路徑。建立或更新的檔案須仍是本批寫入的檔案，且內容與適用屬性仍符合本批結果。已刪除的檔案須仍不存在。計畫為「不變」且不更新紀錄的項目，也須核對規劃時的檔案身分、內容及適用的宣告屬性。提交前發現不符就不提交，完成確認發現不符則依執行失敗處理，若新狀態已寫入，按回復規則處理（FR-APL-001–004、FR-APL-006）。

只變更狀態檔的項目也適用上述提交規則，須核對目標及父路徑的位置、存在狀態，以及既有檔案的身分。直接納管或因內容已符合期望而只更新紀錄時，須確認檔案仍符合期望。接受 drift 須確認內容仍是使用者同意保留的版本。只清除舊紀錄時，須確認舊檔仍不存在。對仍存在的目標，納入比較且適用於目前平台的宣告屬性也須符合規劃結果，直到批次完成。觀測若失效，依執行失敗處理，回報該項未完成（FR-MAN-015、FR-MAN-021、FR-DRF-002、FR-DRF-006、FR-DRF-015、FR-APL-001–002）。

回復也須守住 home 邊界，並確認操作當下的目標及父路徑仍對應本批操作後的位置與狀態。回復建立或更新的檔案前，須確認檔案身分、內容及適用屬性仍符合本批結果。還原已刪除的檔案前，須確認原父目錄仍在原位，且目標仍不存在。讀取快照時，須確認實際讀取的副本仍是本批在受保護位置保存的完整快照。遇到條件不符或無法確認的項目，保留現況並回報路徑及原因，繼續回復其他可安全處理的項目（DC-002、SEC-002、FR-APL-002–004）。

`StateStore` 首次載入、擷取原狀態、提交及回復時，須核對實際操作的狀態檔與父路徑、home 邊界，以及該步驟預期的存在狀態。狀態檔存在時，須核對實際檔案的類型及身分。首次載入的狀態作為規劃基準。擷取時須核對實際保存的回復副本與首次載入的版本相符。替換前須確認當前狀態仍符合原版本。替換後須確認狀態檔仍為本批寫入的版本，才可回報提交成功。若無須寫入新狀態，仍須確認本批依賴的原狀態版本有效，直到判定批次完成。回復前須確認取用的副本仍是本批保存的完整版本，並核對目前狀態是否符合本批操作後的結果。若原狀態未受本批改動，無須回寫。若狀態檔或父路徑已被外部改動或無法確認，保留現況、回報失敗，並繼續回復可安全處理的輸出（DC-002、SEC-002、FR-APL-001–004、REL-002、REL-004）。

管理與初始化的實際寫入也受 home 邊界約束，包含納入管理時的來源副本、manifest 變更及初始化的暫存與本機設定。若操作當下發現路徑遭替換或無法安全確認，該子指令回報失敗，並保護替代位置的檔案（DC-002、IF-007）。

SRS 假設同一組目標同時只有一個 rosamta 程序在套用，且目標所在檔案系統支援單次操作替換（AS-5、AS-6）。以寫入鎖協調 rosamta 程序，並依各平台的能力綁定實際操作和重檢。其他程式仍可修改檔案。檔案系統缺少替換能力時，須確認替代操作、失敗行為及保護範圍。其他程式搬移目錄時的 home 寫入限制見 SRS §3.5。

## 5. 驗證情境

以固定輸入驗證決策規則，在實際檔案系統測試替換、權限、符號連結與程序中止。故障注入須到達指定同步點；若平台阻止外部操作，須確認擋下的是該次注入，並核對原操作按計畫完成或回報原有錯誤。未到達同步點時重測。

在未初始化、沒有來源目錄且無網路的環境，逐一顯示各子指令的說明，核對用途、參數、可能的 exit code 與至少一個範例（IF-002）。

| A11 保留位置碰撞 | 將啟用輸出的目標指向狀態檔、來源、本機設定及其他保留位置，涵蓋路徑別名、目標尚不存在及動作為「不變」。預檢指出衝突並回傳 `1`，所有輸出與狀態檔維持原狀。另讓有效狀態檔中的舊紀錄指向保留位置，而且未由啟用輸出接續管理。清除保留該檔與紀錄，並回報 `reserved`。只有該保留項目時回傳 `1`，同批另有完成項目時，該輸出照常寫入並記錄，回傳 `2` | FR-PLN-007、FR-APL-001、FR-APL-005、FR-APL-007–009、DATA-005 |
| A12 管理指令的路徑保護 | 執行納入管理，於來源副本即將寫入前將其父目錄換成指向 home 外的連結。確認指令回傳 `1`，且外部目錄沒有新增檔案，既有同名檔案亦維持原樣。另讓其他輸出引用預定位置的既有來源檔，並測試在最後一次檢查後才占用預定位置。兩種情境皆須保留原檔與既有宣告，成功時新宣告應引用另一處新副本，失敗時則不新增宣告。另在 manifest 即將寫入時替換其父目錄，確認回報失敗且替代位置的檔案不變 | DC-002、FR-MAN-023、IF-007 |
| A13 輸出原文與副本 | 依 SEC-001 用含標記字串的輸出測試套用，並對接受 drift 的實際內容重測。核對狀態檔格式與內容，確認找不到標記字串，也沒有可還原的輸出原文。分別在暫存檔、快照與備份建立時及中止程序後，以其他一般帳號依測試環境驗證存取限制。Linux 與 macOS 另驗證備份保留原檔權限 | SEC-001、SEC-003、FR-DRF-006 |
| A14 只更新狀態的項目 | 分別規劃直接納管、接受 drift、目標已符合新期望而須更新紀錄，以及移除已確認不存在的舊檔紀錄。在提交前重檢之前與重檢之後各注入一次外部變更，依案例改動檔案內容或讓舊檔重現。Linux 與 macOS 另測只將原先符合宣告的權限 `0600` 改為 `0644`。重檢前的改動應阻止提交，較晚的改動在提交後的完成確認才發現，並依回復規則還原原狀態。兩種情況均須保留外部改動、回報失敗，且不將該項列為完成 | FR-MAN-015、FR-MAN-021、FR-DRF-002、FR-DRF-006、FR-DRF-015、FR-APL-001–002、FR-APL-008 |
| A15 新輸出沿用已不存在的舊路徑 | 保留舊狀態紀錄、移除舊檔，讓新輸出沿用同一路徑。套用後應有新檔與新紀錄，舊紀錄應移除。另在最後一次確認位置為空後、實際建立前，由外部程式先寫入同名檔案。再測提交前重檢之後由外部程式替換本批建立的檔案。兩種情境均須回報失敗、保留外部檔案。後一情境由完成確認發現不符，依回復規則處理已提交的新狀態 | FR-DRF-015、FR-APL-001–002、FR-APL-008 |
| A16 快照與接管備份的讀取 | 先讓同批另一項完成寫入。分別在擷取快照及製作接管備份的最後一次路徑檢查後、開檔前，把父目錄換成另一個含同名檔案的目錄。替代檔案的內容須與原檔不同。若換目錄成功，於原定寫入前換回，確認套用未讀取替代檔案的內容、回傳 `1`、保留原檔與替代檔，並回復其他可安全處理的項目。再於擷取快照或接管備份時直接改動原檔內容，維持到擷取或核對結束才改回。若改動成功，確認套用回傳 `1`、停止變更該目標、保留原狀態，並回復同批已變更且可安全處理的項目。另在擷取時改動原檔，這次於擷取完成後、核對副本前改回。確認仍會拒絕錯誤或混有不同版本的副本，並得到相同的失敗結果。以支援權限設定的平台重測，只改動原檔權限。另驗證成功接管的備份可取回規劃時的原檔版本。最後在回復前替換或破壞某項快照，確認不使用該快照、回報未能回復的路徑與原因，並繼續回復其他項目 | DC-002、SEC-002、FR-APL-002–004、FR-APL-008、FR-MAN-019 |
| A17 寫入後至判定完成前的外部變更 | 讓一般建立及更新成功後，以內容相同的另一個檔案替換目標，分別在操作後第一次查驗身分之前及提交前重檢之後測試。前者由操作後檢查發現，後者由提交後的完成確認發現並依回復規則還原原狀態。另準備覆寫後兩份比較基準都不變的案例。確認對照組成功且免提交狀態後，分別在完成確認前注入同內容替換或移除狀態紀錄。確認能發現目標或狀態不符。各失敗情境均須回傳 `1`、保留外部變動、不將該項列為完成，並還原其他可安全回復的項目 | FR-APL-001–004、FR-APL-006、FR-APL-008 |
| A18 不支援的檔案類型 | 以目錄測試未受管理、未獲接管授權的目標，並在支援 FIFO 的平台以無寫入端的 FIFO 重測。該項保留，不開啟讀取，另一項照常完成，回傳 `2`。另把舊輸出換成上述類型後停用，確認保留原路徑與紀錄。再測不支援的來源與需要接管的目標，確認預覽與套用回報路徑及類型、回傳 `1`，並保留輸出與狀態檔。若最後一次檢查後才換入特殊檔案，確認套用回傳 `1`，保留替代檔案，回復其他可安全處理的項目。再對已停用的舊輸出測試上層目錄缺失或由一般檔案阻擋，確認只清紀錄且不改動阻擋檔。相同阻擋若出現在啟用輸出，且本批不會移除它，預檢須回報 `preflight.unsupported-type`。舊輸出觀測發生 I/O 讀取錯誤時，須回報 `plan.inspect-failed` 並中止整批，輸出及狀態檔不寫入。各次均須在測試時限內結束 | FR-MAN-019–020、FR-DRF-012–013、FR-PLN-007、FR-APL-002–004、FR-APL-007–008、DC-003 |
| A19 清除或覆寫前就地修改 | 分別規劃清除未修改的舊檔和更新仍啟用的輸出。第一次在預檢後、重檢前修改目標。第二次在最後一次內容核對後、實際清除或覆寫前修改。兩次均在同一檔案上寫入不同內容。重檢發現不符時，套用須回傳 `1`，保留外部修改及原狀態，並回復其他可安全處理的項目。較晚的改動依平台驗證是被擋下，或由交換、移開後的檢查發現。檔案系統不支援交換式改名時，核對退回單次改名的結果，並記錄最後一次核對與取代之間的空窗 | FR-DRF-012–013、FR-APL-001–004、FR-APL-008 |
| A20 狀態檔操作遇到路徑替換 | 分別在首次載入狀態、擷取原狀態及提交時，於最後一次路徑檢查後、實際操作前替換狀態檔的父目錄。測試回復時，先替換狀態檔，再讓 `StateStore.commit` 的寫入確認失敗。回復的最後一次路徑檢查通過後、回寫前，替換父目錄。各情境都測指向 home 外的連結及 home 內的替代目錄。若替換成功，確認套用回傳 `1`，替代位置的狀態檔內容未被讀取或改動，也沒有新檔。回報原狀態是否可安全保留或還原，其他可安全處理的輸出須回復 | DC-002、SEC-002、FR-APL-001–004、FR-APL-008、REL-002、REL-004 |
| A21 回復前就地修改輸出 | 分別完成建立與更新，再讓同批另一項失敗以觸發回復。分別在回復重檢前，以及最後一次內容核對後、實際回復前直接改動同一檔案的內容。若改動成功，確認套用回傳 `1`、保留外部修改，並回報未回復的路徑與原因。其他可安全處理的項目須回復。以支援權限設定的平台重測兩個時點，只改動檔案權限 | FR-APL-002–004、FR-APL-008 |
| A22 清除後路徑重新占用 | 完成清除後，分別在重檢前及最後一次目標重檢後、狀態替換前，在同一路徑建立另一個檔案。若建立成功，確認套用回傳 `1`，保留外部檔案與原狀態，回報清除未完成。再讓其他項目失敗以觸發回復，在回復最後一次確認路徑為空後、還原舊檔前建立另一個檔案。若建立成功，確認外部檔案保留，並回報該路徑無法回復。兩種情境皆須回復其他可安全處理的項目 | FR-DRF-012、FR-APL-001–004、FR-APL-008 |
| A23 狀態檔就地修改 | 在提交的最後一次內容核對後、替換前修改原狀態檔。另先替換狀態檔，再讓 `StateStore.commit` 的寫入確認失敗，於回復的最後一次內容核對後、回寫前修改狀態檔。兩次都直接改動同一檔案。若修改成功，確認套用回傳 `1`，保留外部修改，回報狀態提交或回復失敗，並回復其他可安全處理的輸出 | FR-APL-001–004、FR-APL-008、REL-002、REL-004 |
| A24 套用使用預檢版本 | 分別在預檢通過後、第一筆寫入前，以及第一筆寫入後，將後續輸出的來源換成越界連結或來源目錄內另一份內容。確認套用使用預檢確認的版本，執行時未重新開啟來源。另讓執行期參照無法取得已確認的內容，確認套用回傳 `1`，未提交新狀態，且其他可安全處理的項目已回復 | FR-MAN-005、FR-PLN-006–007、FR-APL-001–004、FR-APL-008 |
| A25 原狀態回復副本的版本 | 先載入原狀態，在擷取回復副本時就地寫入另一份格式正確的狀態，讓副本讀到改動後的內容，再於核對前改回原版本。若改動成功，確認套用辨識實際副本有誤、回傳 `1`，保留原狀態並回復其他可安全處理的輸出。另在替換狀態檔後讓 `StateStore.commit` 的寫入確認失敗，分別以完整副本和遭改動的副本測試回復。完整副本須能還原原狀態。副本遭改動時，須保留現況並回報狀態無法回復 | FR-APL-001–004、FR-APL-008、REL-002、REL-004 |
| A26 不變輸出的完成判定 | 規劃一項不寫目標也不更新紀錄的「不變」輸出。分別在同批須寫入新狀態及全批免寫狀態時，於提交前重檢之後、完成確認前就地改動其內容。若改動成功，完成確認須發現不符、保留外部修改、維持或安全還原原狀態、回傳 `1`，並回復其他可安全處理的項目 | FR-APL-001–004、FR-APL-006、FR-APL-008 |
