# 設計分析

## 1. 分析基準

需求範圍與驗收條件以 [SRS 1.1](../02-srs/srs.md) 為準。[初步設計 UML](../03-preliminary-design/uml.md) 的 C1–C4 用於核對責任分工，S1–S6 用於核對執行順序。設計選擇由團隊審查，與驗證情境及待定事項一併交給[詳細設計](../05-detailed-design/detailed-design.md)。

Royce 在圖 5 把初步程式設計放在分析之前，以便及早檢查執行時間、儲存空間、資料流和作業系統介面的限制。本專案先用 UML 分析跨平台寫入、接管與回復，再依圖 7 規劃小型驗證，優先檢驗最可能影響設計的假設。 [Royce，1970，圖 5、7](https://www.praxisframework.org/files/royce1970.pdf)

依 Valente 第 4 章，用類別圖核對資料與責任歸屬，用循序圖核對各情境的訊息與順序。各指令的術語與規則是否一致，依第 5 章的概念完整性判斷。服務分工則以資訊隱藏、內聚與耦合評估。依第 8 章，決策規則可獨立檢查，整合行為須在實際檔案系統驗證。 [第 4 章](https://softengbook.org/chapter4) · [第 5 章](https://softengbook.org/chapter5) · [第 8 章](https://softengbook.org/chapter8)

第一版須涵蓋全部 `essential` 需求。互動處理、一次列出所有預檢錯誤、依賴檢查、機器可讀輸出與效能目標屬於 `conditional` 需求。團隊評估後確認納入或延後，並依 SRS §2.6 與附錄 A.3 記錄結果。

## 2. 系統分工與設計選擇

沿用 C4 的單一 CLI 程序。查詢共用有效設定、Profile 判定、欄位解析與範本引用資訊，清單也包含套用計畫之外的輸出。

| 選項 | 影響 | 分析結論 |
| --- | --- | --- |
| 預覽與套用各自規劃，或共用計畫 | 各自規劃需要同步維護目標路徑、drift、接管與清除的判定，容易使兩者出現差異 | 共用 `Planner` 的判定與計畫資料。CLI 傳入操作模式，`ApplyService` 依模式回傳預覽資料，或在整批預檢與模式檢查通過後執行（FR-PLN-001、FR-PLN-006） |
| 邊檢查邊寫入，或先完成整批計畫再執行 | 邊檢查邊寫入時，可能在部分輸出已變更後才發現目標碰撞 | `PreflightChecker` 在執行前完成阻擋檢查。`Executor` 只接收可執行的計畫，執行失敗時轉入回復流程（FR-PLN-007、FR-APL-002） |
| 各服務各自操作平台 API，或集中處理檔案與狀態操作 | 分散處理容易讓接管、清除及回復對符號連結和權限採用不同規則 | `FileSystem` 封裝平台的路徑與檔案操作。`StateStore` 封裝狀態格式與讀寫結果。`Planner` 使用檢查結果做決策，`RecoveryManager` 保存及恢復批次執行前的狀態（SEC-002、REL-001–004、PORT-001） |

| 責任 | 所需資料與結果 | 需求與 UML |
| --- | --- | --- |
| 設定載入與欄位解析 | `ConfigLoader` 載入內建資源與使用者設定，保留診斷的來源位置。Profile 判定本機啟用的輸出。`ValueResolver` 依內建預設值、使用者模組、Profile、本機設定的順序覆寫，並保留最終值的來源。同一層重複設定時回報各來源 | FR-MOD-001–003、FR-MAN-011、FR-MAN-029、FR-PRF-005–013、DATA-001–004；C1、C2、C4 |
| 範本與原樣複製 | 範本產生期望內容並提供可查詢的欄位引用。原樣複製保留來源位元組，欄位引用為空。內建範本須附目標程式與其設定格式版本 | FR-TPL-001–003、FR-TPL-006、FR-QRY-003、FR-QRY-004；C1、C4 |
| 預覽與套用 | 規劃使用有效設定、主機與路徑資訊、最終欄位值、目標現況和狀態紀錄。預覽提供計畫、差異及預計如何處理衝突。執行時取得項目的期望內容或執行期參照，並回報逐項結果、保留原因、接管備份位置及適用的回復資訊 | FR-PLN-001–010、FR-MAN-019、FR-APL-001–009、FR-DRF-003；C3、C4、S1、S5 |

## 3. 關鍵流程分析

### 3.1 判定目標、接管與清除

`Planner` 先判定啟用的輸出與目標路徑，再按同一套平台路徑規則檢查碰撞與 home 範圍。來源、本機設定、狀態、備份與暫存檔同樣受 home 寫入限制。目標是符號連結時，檢查連結本身。父目錄解析後若使寫入位置超出 home，須攔下操作（FR-MAN-007–010、FR-PLN-009、FR-PLN-010、DC-002、DC-003、SEC-002）。

| 觀察結果 | 決策 | 依據 |
| --- | --- | --- |
| 狀態檔不存在 | 以空紀錄規劃，將既有目標視為未受管理 | REL-003；S1、S2 |
| 狀態檔讀取失敗或損毀 | 預檢失敗，指出狀態檔路徑，保留既有輸出與狀態檔 | REL-004；S1 |
| 一般檔案無紀錄，且內容已符合期望 | 直接記為受管理，保留內容並省略接管備份。之後停用或移除仍適用清除規則 | FR-MAN-021、FR-DRF-012；S2、S4 |
| 一般檔案無紀錄，且內容與期望不同 | 有接管授權時先備份，再寫入並回報備份位置。其餘保留並說明原因 | FR-MAN-018–022；S2 |
| 目標本身是符號連結 | 視為未受管理。有接管授權時備份連結本身，再以一般檔案取代連結。其餘保留連結。兩種情況皆須保護連結所指的檔案 | SEC-002、DC-003；補足 S2 的分流 |
| 原受管理輸出已移除、停用或改路徑 | 未被修改的舊檔刪除並清紀錄。被修改的舊檔預設連同紀錄保留。舊檔已不存在時只清紀錄。已停止管理的輸出保留目標檔，後續清除也須略過 | FR-DRF-012–017、FR-MAN-025；S4 |

若清除舊輸出和寫入新輸出指向同一個實體路徑，05 須訂出唯一的操作順序或阻擋條件。用同一路徑換用另一個輸出名稱，驗證已寫入的新輸出不會被清除。

### 3.2 Drift 與狀態紀錄

詳細設計方案沿用 C3 的兩份比較基準。接受 drift 時，實際基準記錄目前目標的比較資訊，用來判斷目標是否再被改動。期望基準記錄當時產生結果的比較資訊，用來判斷來源是否產生新內容。只存實際基準就無法判斷後者。狀態檔保存輸出名稱、目標路徑及比較資料，與本機設定一同放在來源目錄外。輸出內容與回復快照各自管理（FR-DRF-001–008、DATA-005、DATA-006、SEC-001；C3、S3）。

假設目標原為 `A`，遭外部修改為 `B`，期望仍為 `A`。接受後實際基準為 `B`，期望基準為 `A`。原樣重跑時維持 `B`。目標再次改為 `C` 時，重新判定 drift。若納入 FR-DRF-008，且只有來源變更使期望內容改為 `D`，預覽顯示一般更新 `B` → `D`。內容已符合本次期望時依 FR-DRF-002 更新紀錄，再依平台與權限宣告判斷是否仍須處理屬性。

嚴格模式採 UML §12 已確認的優先序。只要有 drift 衝突，即使指定接受或覆寫，仍須列出衝突的輸出名稱與目標路徑，整批停止且回傳 `1`。嚴格模式下若只有未接管項目被保留，其他項目可照常執行。全部完成或計畫為空回傳 `0`，完成和保留並存回傳 `2`，只有保留回傳 `1`（FR-DRF-009、FR-APL-006–008；S1、S3、S5）。

### 3.3 寫入、儲存與回復

套用開始後，`RecoveryManager` 先取得原狀態檔的回復資訊，再為每個待變更項目保存套用前的內容、適用權限及存在與否。接管備份須在取代目標前完成。每個檔案先備妥完整新內容，再以平台支援的方式替換。全部目標操作成功後才提交新狀態。若中途操作或提交狀態失敗，回復已變更的目標與原狀態，並回報原錯誤及未能恢復的各路徑和原因。接管備份用於讓使用者取回原檔，批次快照用於程式回復（FR-APL-001–005、FR-MAN-019、REL-001、REL-002；S2、S5）。

若較早的項目已接管符號連結，回復須能還原連結本身，並保護它所指的檔案。程序被強制終止時，依 REL-001、REL-002 檢查單一輸出或狀態檔是否保持完整。分別估算期望內容、單次替換的暫存檔、累積的回復快照與接管備份所需的空間，並評估磁碟空間不足時哪些操作可能失敗。

SRS 假設同一組目標同時只有一個 rosamta 程序在套用，且目標所在檔案系統支援單次操作替換（AS-5、AS-6）。05 須釐清如何辨識這些前提，並處理預檢後被外部程式改動的目標。多個程序的互斥方式與不支援替換的平台診斷仍須評估。

## 4. 詳細設計前的技術評估

| 選擇 | 候選方向與取捨 | 定案依據 |
| --- | --- | --- |
| 使用者設定格式與編輯 | 選擇支援 UTF-8 和註解的格式，並比較能保留來源格式的語法樹編輯與依來源位置局部修改。前者可集中處理語法與診斷，後者可縮小改動範圍，但須處理不同結構的新增和刪除 | 以含註解、空行、不同縮排與換行的設定測試納入、修改、停止管理與本機設定合併。比較未修改區域的位元組，並確認錯誤可指出位置（IF-010、FR-MAN-029、FR-MAN-030、FR-INI-008） |
| 範本語言 | 比較限制存取能力的現有引擎與小型自訂語法。既有引擎可減少自建語法的成本。自訂語法可直接控制欄位參照的表示，但需自行維護語法、錯誤訊息與相容性 | 驗證渲染與引用查詢能共用一套欄位參照規則，涵蓋條件分支及未啟用輸出。範本能力須維持預覽的限制，並為公開語法與函式建立相容性案例（FR-TPL-001–003、FR-QRY-003、FR-QRY-004、FR-PLN-005、MNT-001） |
| 實作語言與檔案操作 | 先篩選可產出各平台獨立執行檔的工具鏈。共用檔案介面可減少上層對平台的依賴，個別平台的替換、連結與權限行為仍需實測 | 在三平台以一般使用者測試單檔替換、符號連結接管、回復與單一執行檔發佈（DC-001–004、SEC-002、REL-001、REL-002、PORT-001） |

## 5. 驗證情境

表列案例供 05 的小型原型和 [06 測試計畫](../06-test-plan/test-plan.md) 使用。決策規則可先用固定輸入檢查。檔案替換、權限、連結與程序中止須在實際檔案系統驗證。

| 案例 | 操作與預期結果 | 需求 |
| --- | --- | --- |
| A1 欄位來源與輸出清單 | 讓四層都設定同一欄位，逐層移除設定後檢查值及來源。另讓兩個同層來源設定同欄位，檢查預檢失敗與來源診斷。完整清單仍可列出內建與未啟用輸出，模組查詢也涵蓋未啟用的引用 | FR-PRF-009–013、FR-MAN-026、FR-QRY-001、FR-QRY-004 |
| A2 預覽與預檢 | 在相同輸入下先預覽再套用，比對逐項動作。再讓最後一項發生正規化路徑碰撞，檢查全部輸出與狀態均維持原樣 | FR-PLN-004、FR-PLN-006、FR-PLN-007、FR-PLN-009、FR-PLN-010 |
| A3 納管及連結接管 | 移除狀態檔後以內容相同的一般檔案重新納管。另以指向 home 外檔案的連結分別測試保留及接管。接管時回報可用備份，該目標成為一般檔案，連結原本指向的檔案不變 | REL-003、FR-MAN-019–021、SEC-002 |
| A4 接受與嚴格模式 | 按 §3.2 驗證接受後重跑及再次外部修改。嚴格模式下，有 drift 衝突時應回傳 `1`。無 drift 但有一項保留、一項完成時應回傳 `2` | FR-DRF-001、FR-DRF-006–009、FR-APL-007、FR-APL-008 |
| A5 清除與停止管理 | 對未改、已改及已不存在的舊檔驗證刪除、保留及只移除紀錄三條路徑。再停止管理一個內建輸出，重新載入後仍保留原檔，也不重新列入套用 | FR-DRF-012、FR-DRF-013、FR-DRF-015、FR-DRF-016、FR-MAN-025 |
| A6 回復及單檔完整性 | 注入中途寫入失敗、狀態提交失敗與部分回復失敗，檢查目標及原狀態的回復和診斷。目標涵蓋一般檔案與原為連結的項目。另在替換時強制終止程序，分別檢查輸出與狀態檔的完整性 | FR-APL-002–004、FR-APL-008、REL-001、REL-002、SEC-002 |
| A7 初始化失敗與首套用 | 用無法取得的遠端驗證沒有建立正式來源、本機設定或輸出，並回報位址與原因。另以可取得的測試 repo 驗證 HTTPS、SSH，以及首次套用保留一項、完成一項時回傳 `2` | IF-012、FR-INI-001、FR-INI-009–011 |
| A8 時間與空間 | 若納入效能目標，依 SRS 在參考機器上先套用一次，再量測 500 個輸出皆不變時的 10 次套用。執行時間的中位數須小於 1 秒。另測試多個大檔與磁碟空間不足的情境，觀察暫存及快照的用量和回復結果 | PERF-001、FR-APL-002、REL-001、REL-002 |
| A9 範本與原樣複製 | 用含條件分支的範本核對渲染與引用查詢，並驗證覆寫單一內建範本時其他輸出維持原樣。用含範本符號與非 UTF-8 位元組的來源驗證原樣複製，輸出須與來源逐位元組相同 | FR-TPL-003、FR-TPL-006、FR-QRY-003、FR-QRY-004 |

## 6. 文件對齊與交接

| 對齊事項 | 04 採用的依據與後續處理 |
| --- | --- |
| 未受管理的判定 | 依 REL-003、FR-MAN-021、SEC-002 與 §3.1。SRS 詞彙表可另行對齊，明確區分狀態紀錄、一般檔案與符號連結 |
| 整批預檢與錯誤彙整 | FR-PLN-007 的寫入前檢查是必做。S1 所述一次收集所有錯誤依 USE-004 的 `conditional` 分期 |
| 完整輸出清單、預覽與接管回報 | 05 依 §2 的查詢責任與回報內容補上介面和資料模型，對應 FR-MAN-026、FR-PLN-003、FR-MAN-019 |
| 嚴格模式與互動 | 嚴格模式優先依 UML §12。非嚴格模式下明確處理選項與互動提示的優先序，待互動功能納入時確認 |
| 預覽與套用的一致性 | FR-PLN-006 明列來源、本機設定及目標路徑。狀態紀錄可在目標內容不變時更新，例如接受 drift。驗證時也固定狀態、主機資訊及適用選項，由團隊確認是否在 SRS 補述比較前提 |
| 查詢驗收與分期 | FR-QRY-004 的驗收文字同時引用模組查詢及 `conditional` 的欄位查詢。04 依正式優先序規劃兩種情境，由團隊確認並透過 SRS 修訂釐清欄位查詢延後時的驗收方式 |

05 須定義設定、範本及執行介面，並完成 UML §12 的五項設計，包括接管備份的命名及保留規則、比較資料的格式與演算法、預檢後重檢與多程序協調、平台路徑與連結檢查，以及內建輸出停止管理的持久化表示。06 依 SRS 的需求編號與驗收條件編寫案例，納入本文件的分支及故障情境。
