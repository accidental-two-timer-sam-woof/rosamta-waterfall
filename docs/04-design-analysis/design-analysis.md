# 設計分析

## 1. 分析基準

需求範圍與驗收條件以 [SRS 1.1](../02-srs/srs.md) 為準。[初步設計 UML](../03-preliminary-design/uml.md) 的 C1–C4 用於核對責任分工，S1–S6 用於核對執行順序。設計選擇由團隊審查，與驗證情境及待定事項一併交給[詳細設計](../05-detailed-design/detailed-design.md)。

Royce 在圖 5 把初步程式設計放在分析之前，以便及早檢查執行時間、儲存空間、資料流和作業系統介面的限制。本專案先用 UML 分析跨平台寫入、接管與回復，再依圖 7 規劃小型驗證，優先檢驗最可能影響設計的假設。 [Royce，1970，圖 5、7](https://www.praxisframework.org/files/royce1970.pdf)

依 Valente 第 4 章，用類別圖核對資料與責任歸屬，用循序圖核對各情境的訊息與順序。各指令的術語與規則是否一致，依第 5 章的概念完整性判斷。服務分工則以資訊隱藏、內聚與耦合評估。依第 8 章，決策規則可獨立檢查，整合行為須在實際檔案系統驗證。 [第 4 章](https://softengbook.org/chapter4) · [第 5 章](https://softengbook.org/chapter5) · [第 8 章](https://softengbook.org/chapter8)

第一版須涵蓋全部 `essential` 需求。互動處理、一次列出所有預檢錯誤、依賴檢查、機器可讀輸出與效能目標屬於 `conditional` 需求。團隊評估後確認納入或延後，並依 SRS §2.6 與附錄 A.3 記錄結果。

## 2. 系統分工與設計選擇

沿用 C4 的單一 CLI 程序。查詢共用有效設定、Profile 判定、欄位解析與範本引用資訊，清單也包含套用計畫之外的輸出。

| 選項 | 影響 | 分析結論 |
| --- | --- | --- |
| 預覽與套用各自規劃，或共用計畫 | 各自規劃需要同步維護目標路徑、drift、接管與清除的判定，容易使兩者出現差異 | 共用 `Planner` 的判定與計畫資料。CLI 傳入操作模式，`ApplyService` 依模式回傳預覽資料，或在整批預檢與模式檢查通過後執行（FR-PLN-001、FR-PLN-006） |
| 邊檢查邊寫入，或先完成整批計畫再執行 | 邊檢查邊寫入時，可能在部分輸出已變更後才發現目標碰撞 | `PreflightChecker` 在執行前完成阻擋檢查。`Executor` 只接收可執行的計畫，執行失敗時轉入回復流程（FR-PLN-007、FR-APL-002） |
| 各服務各自操作平台 API，或集中處理檔案與狀態操作 | 分散處理容易讓接管、清除及回復對符號連結和權限採用不同規則 | `FileSystem` 封裝平台的路徑與檔案操作。`StateStore` 封裝狀態格式與讀寫結果。`Planner` 使用檢查結果做決策，`RecoveryManager` 保存及恢復批次執行前的狀態（SEC-002、REL-001–004、PORT-001） |

| 責任 | 所需資料與結果 | 需求與 UML |
| --- | --- | --- |
| 設定載入與欄位解析 | `ConfigLoader` 載入內建資源與使用者設定，保留診斷的來源位置。Profile 判定本機啟用的輸出。`ValueResolver` 依內建預設值、使用者模組、Profile、本機設定的順序覆寫，並保留最終值的來源。同一層重複設定時回報各來源 | FR-MOD-001–003、FR-MAN-011、FR-MAN-029、FR-PRF-005–013、DATA-001–004；C1、C2、C4 |
| 範本與原樣複製 | 範本產生期望內容並提供可查詢的欄位引用。原樣複製保留來源位元組，欄位引用為空。內建範本須附目標程式與其設定格式版本 | FR-TPL-001–003、FR-TPL-006、FR-QRY-003、FR-QRY-004；C1、C4 |
| 預覽與套用 | 規劃使用有效設定、主機與路徑資訊、最終欄位值、目標現況和狀態紀錄。預覽提供計畫、差異及預計如何處理衝突。執行時取得項目的期望內容或執行期參照，並回報逐項結果、保留原因、接管備份位置及適用的回復資訊 | FR-PLN-001–010、FR-MAN-019、FR-APL-001–009、FR-DRF-003；C3、C4、S1、S5 |
| 管理與查詢 | `ManifestService` 負責納入、修改屬性與停止管理，並保留設定檔未受影響的註解及格式。完整輸出清單由 `QueryService` 使用有效 manifest 與 Profile 取得，包含內建與未啟用輸出的屬性、當前平台路徑及啟用狀態。查詢引用時再按模組、欄位或輸出篩選 | FR-MAN-023–026、FR-MAN-030、FR-PRF-013、FR-QRY-001–004、FR-QRY-006；C1、C2、C4 |
| 初始化 | `InitializationService` 處理來源與本機設定。指定遠端時，先在暫存位置取得來源，成功後才移入正式位置並建立或合併本機設定。未指定遠端時支援建立空來源與空 manifest。來源就緒後，第一次套用沿用一般預檢、回報與 exit code | FR-INI-001、FR-INI-002、FR-INI-004、FR-INI-006、FR-INI-008–011、IF-012、IF-013；C4、S6 |

每次規劃使用同一份主機資訊、Profile 啟用結果與狀態紀錄。S3 的比較資訊可取自 S1 交給 `Planner` 的紀錄。執行前若須重檢，應區分規劃時的觀測與執行前的現況。用相同輸入核對預覽與套用的計畫（FR-PLN-006；S1、S3）。

CLI 將計畫與執行回報送到標準輸出，將錯誤與警告送到標準錯誤。預覽和查詢都須維持唯讀。若納入互動功能，只有明確啟用互動且標準輸入連接終端機時才詢問。所有必做功能須在 Linux、Windows、macOS 以一般使用者權限運作，並能以各平台的單一執行檔發佈。初始化取得遠端來源可使用 git（IF-007、IF-008、IF-013、USE-001、USE-002、DC-001、DC-004、PORT-001）。
